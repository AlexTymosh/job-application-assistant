# Local Private Profile Setup

The repository contains only fake example profile data. Real private profile data, real CV files, generated application artefacts, and SQLite databases must live outside the repository.

## Recommended Windows location

```text
C:/Users/<user>/job-application-assistant-data/alex/
```

Use your own profile name instead of `alex` if preferred. Do not create or commit `profiles/alex/` in the repository.

## Expected private profile structure

```text
C:/Users/<user>/job-application-assistant-data/alex/
├── config.yaml
├── blacklist.txt
├── applications.sqlite3              # generated by Alembic/runtime
├── applications/                     # generated artefacts
└── cv/
    ├── master.md
    ├── fact_bank.yaml
    └── variants/
        └── backend_developer.md
```

## Required `config.yaml` shape

```yaml
app:
  profile_name: "alex"
  data_dir: "C:/Users/<user>/job-application-assistant-data/alex"

workflow:
  require_human_approval_before_export: true
  stop_on_blacklist: true
  warn_on_duplicate: true
  stop_on_prompt_injection: false

llm:
  provider: "openai"
  model_extract: "${OPENAI_MODEL_EXTRACT}"
  model_tailor: "${OPENAI_MODEL_TAILOR}"
  model_qa: "${OPENAI_MODEL_QA}"
  temperature_extract: 0.0
  temperature_tailor: 0.2
  temperature_qa: 0.0
  use_structured_outputs: true

cv:
  default_variant: "backend_developer"
  variants:
    - "backend_developer"

exports:
  markdown: true
  html: true
  pdf: true
  docx: true

guardrails:
  allow_new_skills: false
  allow_fake_metrics: false
  require_fact_ids: true
  require_evidence_matrix: true
  max_summary_words: 80
  british_english: true

job_reader:
  allow_url_input: true
  allow_manual_text_input: true
  min_extracted_text_chars: 1200

future_integrations:
  reed_api_enabled: false
  auto_apply_enabled: false
```

Do not store secrets in `config.yaml`. Keep `OPENAI_API_KEY` in `.env` or the process environment.

## Required `blacklist.txt` shape

Use one private match value per line. Blank lines and comments are acceptable if supported by the current loader.

```text
# Fake examples only
Example Blocked Company
blocked.example
recruiter@example.invalid
```

## Required `cv/master.md` shape

The master CV must be Markdown and must include section markers:

```md
<!-- SECTION: SUMMARY_START -->
Summary text.
<!-- SECTION: SUMMARY_END -->

<!-- SECTION: SKILLS_START -->
Skills text.
<!-- SECTION: SKILLS_END -->

<!-- SECTION: EXPERIENCE_START -->
Experience text.
<!-- SECTION: EXPERIENCE_END -->

<!-- SECTION: PROJECTS_START -->
Projects text.
<!-- SECTION: PROJECTS_END -->
```

The application must not mutate `master.md` automatically.

## Required `cv/fact_bank.yaml` shape

```yaml
facts:
  - id: fact_fastapi_001
    category: skill
    name: FastAPI
    allowed_claim_level: practical
    evidence: "Used in a backend project."
```

Every significant future CV change must reference verified fact IDs. If there is no `fact_id`, the application must not make the claim.

## Required `cv/variants/*.md` shape

Variant files are Markdown CV files with the same required section markers as `master.md`. Example:

```text
cv/variants/backend_developer.md
```

The selected variant must exist in `config.yaml` and must pass required section marker validation.

## Set the active private profile

PowerShell:

```powershell
$env:PROFILE_NAME = "alex"
$env:PROFILE_DATA_DIR = "C:/Users/<user>/job-application-assistant-data/alex"
```

Then run:

```powershell
uv sync --locked --group dev
uv run alembic upgrade head
uv run uvicorn app.main:app --reload
```

## Verify that no real profile files are tracked

Run from the repository root:

```powershell
git status --short
git ls-files -- profiles/alex C:/Users/<user>/job-application-assistant-data/alex
```

The private external directory should not be inside the repository, so Git should not list those files.

## What not to commit

Do not commit:

- `.env`;
- API keys or tokens;
- real `config.yaml` files;
- real `blacklist.txt` files;
- real `cv/master.md` files;
- real `cv/fact_bank.yaml` files;
- real `cv/variants/*.md` files;
- generated `applications.sqlite3` databases;
- generated application artefacts;
- real cover letters, CV exports, PDFs, DOCX files, or match reports.

## Copying from `profiles/example` safely

You may copy the fake example structure as a starting point:

```powershell
New-Item -ItemType Directory -Force C:/Users/<user>/job-application-assistant-data/alex
Copy-Item profiles/example/config.example.yaml C:/Users/<user>/job-application-assistant-data/alex/config.yaml
Copy-Item profiles/example/blacklist.example.txt C:/Users/<user>/job-application-assistant-data/alex/blacklist.txt
Copy-Item profiles/example/cv -Destination C:/Users/<user>/job-application-assistant-data/alex/cv -Recurse
```

After copying, rename `.example` CV files to private filenames and replace fake content with your own verified private facts outside the repository. Never copy real private data back into `profiles/example`.
